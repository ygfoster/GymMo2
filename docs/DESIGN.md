# GymMo2 設計メモ

元の GymMo（Gemini で作成）と、Apple の Human Interface Guidelines を手本に作り直した GymMo2 を比較検証するための記録です。

## 方針

- **UI のクロームはモノクロ、色はデータにだけ使う。** Apple フィットネスのように、色が「意味」を持つ（カロリー=ピンクレッド、タンパク質=ブルー、脂質=オレンジ、炭水化物=グリーン、睡眠=インディゴ、運動・タイマー=ライム）。
- **端末のライト/ダークに自動追従。** 色はすべて `light-dark()` のトークン（`css/tokens.css`）で一元管理。
- **動きは「意味のある動き」だけ。** iOS のシートと同じ減速カーブ `cubic-bezier(.32,.72,0,1)`、弾みのある操作には物理バネ（`linear()` で近似）。`prefers-reduced-motion` ではフェードのみ。
- **1 画面 1 目的。** 日別ビューを「今日」タブと履歴からの詳細で共用し、同じ見た目・同じ操作にする。

## デザイン言語

| 要素 | GymMo（元） | GymMo2 |
| --- | --- | --- |
| 配色 | ダーク固定、オレンジのブランド色 | ライト/ダーク自動追従。UI はモノクロ、データ色のみ（フィットネス風リング配色） |
| 書体 | Inter + Oswald（英字見出しを大文字・字間広め） | Apple 端末は SF Pro、その他は Inter。見出しは日本語、数字はタブラー数字 |
| ナビゲーション | 下部 5 項目 + 中央に飛び出す巨大ボタン、ハンバーガーで設定 | 標準的なタブバー（今日・履歴・＋・分析・設定）。ラージタイトルがスクロールでインライン表示へ縮む |
| 画面遷移 | 表示/非表示の切替 + 簡易スライド | タブ=フェード、詳細=横スライド（背面は少し暗く奥へ）、記録=下から出るページシート（背面が縮む） |
| プルダウン | 独自ドロップダウン（部位・グラフ種目） | 部位は 1 タップのチップ（前回からの日数つき）、種目は検索つきシート、操作メニューは半透明のコンテキストメニュー |
| 確認・通知 | 全画面モーダル、右上トースト | iOS 風アラート、画面上部のバナー、保存完了は中央の HUD（チェックが描かれる） |
| グラフ | Chart.js（CDN 依存） | 自前 SVG。右端に軸、なぞると値が出て振動、線は描画アニメーション |
| 触覚 | `navigator.vibrate` を固定パターンで | 種類別（選択/タップ/完了/警告/タイマー終了）。設定でオフ可 |

## 機能の比較

### 追加した機能
- **今日のサマリー**: カロリー収支・タンパク質・睡眠のリング（目標は設定で変更）、PFC バランス（カロリー比）、直近 7 日の推移。
- **前回の記録**: 種目名を入れると前回のセットを表示し、ワンタップでコピー。
- **自己ベスト（PR）**: 記録中にリアルタイム判定してバッジ + 触覚 + 効果音。日別・種目別にも表示。推定 1RM は Epley 式（回数は 12 回まで考慮）。
- **分析タブ**: 期間比較つきサマリー、部位別の週間セット数、種目別の 1RM/ボリューム推移（自重種目は回数）、睡眠と重量の関係（サンプル不足のときは出さない）。
- **休憩タイマー**: 2 つのフローティングを 1 本の「ドック」に統合（後述）。
- CSV 書き出し、デモモード、初回パスコード入力、部位ごとの休憩時間、テーマ切替。

### 休憩タイマーの改善（要望対応）
| 課題 | 対応 |
| --- | --- |
| 再生/リセットが小さい | 記録画面下端に固定した 1 本のドック。再生 70px・リセット 54px（Apple の最小 44pt 以上）、時間は 40px |
| 存在感がほしいが画面操作を邪魔したくない | 画面に「浮かせる」のをやめ、ドックの分だけ領域を確保（重ならない）。走行中は緑に染まり、リングで残りが見える。他の画面ではミニプレイヤーとして残る |
| セット後にかけ忘れる | セットの ✓ で休憩を**自動開始**（設定でオフ可）。回数を入れて未完了なら ✓ がやさしく脈動。✓ が使われない設定の場合は再生ボタンが脈動 |
| 他のアプリを使っていても残り時間を見たい／画面を閉じても終了を逃したくない | **Android アプリ版**: 通知欄にカウントダウンを表示し、終了は正確なアラームで通知（アプリが終了していても動く）。通知のボタンで一時停止・+30秒・リセット |
| ほか | 絶対時刻ベースで画面オフ・再読込でもずれない／部位ごとの既定時間／Wake Lock／終了時の振動・効果音・（任意で）通知／合計時間はドックに常時表示 |

### 元アプリで見つかった不具合・リスクと、GymMo2 での扱い
| 元アプリ | GymMo2 |
| --- | --- |
| API トークンと Apps Script の URL が **公開リポジトリのコードに直書き**（URL を知れば誰でも読み書き可能） | トークンはコードに含めず、初回にパスコード入力（端末内のみ）。サーバー側の設定ファイルは git 管理外 |
| 起動のたびに**同一オリジンのすべての Service Worker を解除**（同じ `ygfoster.github.io` の Recipe Box にも影響し得る） | Service Worker を正しく登録し、プリキャッシュでオフライン起動。他アプリには触れない |
| `user-scalable=no`（ピンチズーム不可） | 許可（アクセシビリティ） |
| 種目名・メモを `innerHTML` に未エスケープで埋め込み（XSS） | 自動エスケープのテンプレートタグ（テスト済み） |
| 起動時のワークアウト取得は**最新 60 行まで**（超えると古い記録が履歴・累計・グラフから欠ける） | 全期間を取得 |
| 起動のたびに Google ヘルス API を最大 18 回呼ぶ | 起動はシートの読み取りのみ。日別に必要なときだけ取得、定期同期は 1 時間おき |
| 摂取 0 kcal の日を「巨大な赤字」として扱い得る（未記録と区別できない） | 食事が未記録の日はカロリー収支を出さず、集計にも含めない |
| `<title>` が「GmyMo」の誤字 | 修正 |
| 日付の並びが乱れたシート（Health Data）を前提にしていない | 読み込み時に日付で正規化・統合 |

## 技術メモ

- **依存ライブラリなし**（Alpine.js・Chart.js を廃止）。ES Modules をそのまま配信するのでビルド不要。
- **状態**: `store.js`（キャッシュ・オフラインキュー・同期）。保存は楽観的更新 + キュー。接続できないときは端末に保存して自動で再送。
- **ルーター**: ハッシュ + 履歴スタック。Android の「戻る」でシートも閉じる（履歴ガード）。
- **データ形式は元アプリと互換**（`1セット目: 50kg × 11回`）。シートは両アプリから読めるが、**GymMo2 は自分専用の複製シート**に書く。
- **テスト**: ロジック層とバックエンドの純粋関数に 36 件。`scripts/offline-check.mjs` で Service Worker のオフライン起動を実ブラウザ（ヘッドレス Chrome）で検証。

## 既知の制約

- Google ヘルスの取得は、Apps Script 側で Google ヘルスへのアクセス許可（OAuth）を 1 回行った後に有効になる。
- ブラウザ版（PWA）では、休憩終了の通知は画面を閉じているとブラウザの制約で遅れることがある（ベストエフォート）。**Android アプリ版**（`android/`）は、OS の通知（カウントダウン表示）と正確なアラームで動くため、画面オフ・アプリ終了中でも秒単位で鳴る。
- 振動は Android の Chrome のみ（iOS Safari は非対応）。
